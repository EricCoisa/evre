# Internacionalização (i18n)

`nestjs-i18n`, configurado em `backend-nest/src/app.module.ts`.

## Idiomas

- **en** (English) — **fallback** (`fallbackLanguage: 'en'`)
- **pt-BR** (Português)

Arquivos JSON por área em `src/i18n/en/` e `src/i18n/pt-BR/` (`auth.json`, `user.json`, `validation.json`, `common.json`, …). `watch: true` dá hot reload em dev.

## Como o idioma é resolvido

Ordem dos resolvers (`app.module.ts`):

1. **QueryResolver** — `?lang=en`
2. **AcceptLanguageResolver** — header `Accept-Language`
3. **HeaderResolver** — header `x-language`
4. **Fallback** — `en`

```bash
GET /api/v1/auth/me?lang=en
curl -H "x-language: pt-BR" http://localhost:3001/api/v1/user/profile
```

## Usar no código

```ts
constructor(private i18n: I18nService) {}
this.i18n.t('user.welcome', { args: { name } });
```

Fora de um provider, use o contexto da request: `I18nContext.current()?.t('user.statuses.ACTIVE')`.

## Em DTOs (mensagens de validação)

A chave i18n vai como mensagem no schema Zod — é resolvida na resposta de erro:

```ts
const SignUpSchema = z.object({
  password: z.string().min(6),
  acceptTerms: z.literal(true, { errorMap: () => ({ message: 'auth.signup.terms_required' }) }),
});
```

## Adicionar tradução / idioma

- **Nova chave:** adicione a mesma chave em `en/<area>.json` e `pt-BR/<area>.json`.
- **Novo idioma:** crie `src/i18n/<locale>/` com os mesmos arquivos; é detectado automaticamente.

O `plop module` já cria os JSON de i18n do módulo (en + pt-BR). Ver [[add-a-module]].

> [!warning] Chave inexistente não quebra o build — quebra a tela
> `i18n.t('x.y')` devolve a própria string `x.y` quando a chave não existe, e ela
> chega ao usuário como mensagem. O compilador não vê.
>
> `src/i18n/i18n-keys.spec.ts` é o que reclama: falha se alguma chave referenciada
> no código faltar em **qualquer** locale, se os locales divergirem entre si, ou se
> existir arquivo de namespace sem nenhuma referência no código. Rode `npm run test`
> depois de mexer em mensagem.

Mensagem de validação Zod conta como referência: o literal em `.min(6, 'validation.x')`
é resolvido pelo filtro de exceção, então precisa existir nos dois locales.

## Swagger

Em dev, a UI do Swagger (`/api/docs`) é servida traduzida para **pt-BR** por padrão, com opção de trocar para `en` (`main.ts`). Isso é só a doc; o fallback da API continua `en`.

> i18n do frontend é separado (i18next). Ver [[frontend-overview]].
